# Рабочий процесс: Рабочая версия vs GitHub версия

## Проблема
В рабочей версии бота токен хранится прямо в коде `bot.py` для удобства. Но для GitHub это небезопасно — токен не должен попадать в публичный репозиторий.

## Решение
Используйте скрипт `prepare_for_github.py` для автоматической подготовки версии без токена.

## Как использовать

### Перед загрузкой на GitHub:

1. **Подготовить версию для GitHub** (уберет токен из кода):
   ```powershell
   python prepare_for_github.py
   ```

2. **Проверить изменения**:
   ```powershell
   git status
   git diff bot.py
   ```
   Должна быть изменена строка с `BOT_TOKEN` — токен убран.

3. **Закоммитить и загрузить**:
   ```powershell
   git add .
   git commit -m "Remove bot token for GitHub"
   git push
   ```

### После загрузки на GitHub:

**Восстановить рабочую версию** (вернет токен обратно):
```powershell
python prepare_for_github.py restore
```

Теперь бот снова работает с токеном в коде.

---

## Альтернатива: Использовать только .env

Если хотите полностью убрать токен из кода навсегда:

1. Убедитесь, что в `.env` есть строка:
   ```
   BOT_TOKEN=ваш_токен_здесь
   ```

2. В `bot.py` оставьте:
   ```python
   BOT_TOKEN = os.getenv("BOT_TOKEN", "").strip()
   if not BOT_TOKEN:
       raise ValueError("BOT_TOKEN must be set in .env file")
   ```

3. Тогда можно коммитить `bot.py` без изменений — токен всегда будет только в `.env` (который в `.gitignore`).

---

## Рекомендация

**Для портфолио:** Используйте скрипт `prepare_for_github.py` — это показывает, что вы понимаете важность безопасности.

**Для продакшена:** Лучше всегда хранить токен только в `.env`, а не в коде.
